## Verified reference facts

Limitless presents Apple Knight as an action platformer with bosses, traps and direct combat. [Developer site](https://www.limitless.online/index.html). Its developer-supplied App Store listing describes secrets, treasure, equipment and ability upgrades, as well as a separate endless mode. [Official listing](https://apps.apple.com/us/app/apple-knight/id1486055730).

## Design reading and dependencies

Our planning question is not how to avoid resembling any existing platformer. It is what single player decision will make this team's tiny game worth trying.

- A level-based combat-and-collect loop can be enjoyable without interconnected progression. If Vatsal wants discovery through returning with a new ability, that is a structural distinction to test in the map.
- Equipment upgrades demand item data, balancing, UI and compatibility with attacks. For a jam, one earned ability is easier to explain and verify than a shop or loot inventory.
- Traps can do double duty: a hazard teaches timing, then becomes a tool against an enemy. This is a promising way to gain a second interaction from one asset and rule.
- A procedural endless mode is a separate generation and fairness problem. It should not be included merely because rooms look modular.

## Visual and production reading

The [three inspected store views](visual-reference.md) show forest combat, a platforming hazard space and a dragon encounter. Observation: bright player and projectile shapes sit against layered, muted scenery. Terrain edges and hazards remain visually distinct. The boss view also shows how quickly animation and effect counts increase.

Engine, art software, tile size, sprite dimensions and animation export pipeline were not verified from the primary sources checked. They remain unknown; do not describe this as an established Unity or web project.

For our own production, tile repetition and mirrored left/right movement can reduce work, but asymmetrical weapons and hitboxes still need verification. Lock the player's pivot, collision box and facing rules before exporting a large sheet. Mirroring is a proposed simplification, not a claim about this game's implementation.

## Bounded jam takeaway

Prototype a corridor with one enemy, one trap and an optional treasure branch. Then compare it with an ability-gated return loop. Ask Vatsal which experience is closer to what he wants: progressing through stages or learning a small connected place.

A distinguishing rule could be environmental manipulation, a humorous consequence or an unusual traversal interaction. The team should select that rule after the event theme is known. More content is not a substitute for a clear rule.
